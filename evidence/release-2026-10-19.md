## 代码支持的功能

| 功能 | 用户能完成的事 | 实现边界 |
| --- | --- | --- |
| 账号与组织开通 | 邮箱注册、验证、登录、找回/重置密码；注册时开通组织、角色和免费套餐 | 邮件需供应商配置；Google/GitHub OAuth 有实现但本次未验证第三方流程 |
| 多租户工作区 | 查看和切换所属组织、管理工作区及项目 | OrgContextGuard 每次反查有效 Membership；Prisma 租户事务配合 RLS；切换缓存行为需进一步浏览器验收 |
| 组织管理 | 部门树、成员、邀请、角色、菜单权限和数据范围 | 最后有效 OWNER 的移除、停用及角色剥夺有保护；并发正确性本次未重新证明 |
| 邀请 | 邀请、接受、撤销及过期拒绝 | 邮箱/组织/角色绑定，不能把邮件 API 成功等同接受成功 |
| 项目与任务 | 创建项目、修改信息、激活、交付、归档；任务分派和状态管理 | 是企业交付场景基础功能，不代表完整 Jira 类项目管理套件 |
| 文件交付 | 上传、同名升版本、授权下载、带期限共享 | 当前文件写本地 `.uploads`，并非现成的 S3 方案；生产编排未挂载上传卷，后续 API 重建前必须安排文件持久化与备份 |
| 即时消息 | 私聊、群聊、历史、未读/已读、图片/文件附件、实时推送 | Socket.IO + Redis；有消息保留任务；本次未重跑多人实时与断线恢复 |
| 套餐与权益 | 套餐总览、有效席位、套餐沙盒切换、事件处理与生命周期扫描 | `subscribe` 明确为内部模拟；Webhook 是自定义 HMAC 协议，不是已交付 Stripe Checkout/Billing 收款闭环 |
| 系统管理 | 菜单、字典、参数、公告、登录日志、业务审计 | 权限受后端控制；审计包含 actor、资源差异和 trace 信息 |
| 运维监控 | 服务器、数据库、缓存、在线用户、任务列表和手动触发 | 有健康端点、结构化日志、Docker/Terraform/CI 部署代码；备份恢复、告警送达和容灾未验收 |

## 产品定位与未交付能力

现阶段适合定位为：面向咨询公司、外包团队或多客户服务公司的企业协作后台。管理员管理人员与权限，负责人管理项目和文件交付，团队通过即时消息和公告协作，财务查看席位与模拟套餐。

当前源码未发现 WorkOS / SAML / SCIM 的实际接入，不能因为设计文档列出这些组件就宣称企业 SSO 已完成。没有发现 LLM/Agent 业务模块，因此它是协作 SaaS，不是 AI 项目管理产品。真实 Stripe 收款、企业目录同步、可靠对象存储与备份恢复仍是后续交付项。

建议下一阶段先补 ESLint/可执行业务测试、浏览器 AT、文件持久化和备份恢复，再接真实邮件/OAuth/Stripe；生产注册与权限隔离还需要独立安全审查。本次不扩大功能或改动生产数据来替代这些验收。
