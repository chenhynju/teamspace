# SaaS 共用底座：扁平组织与资源接口

## 领域概念

租户（Organization）是数据、成员资格、账单和审计的硬边界。它不是组织架构树的根节点。任何授权均不能跨租户扩张。

协作单元（CollaborationGroup）是抽象组织的第一种实现，可标记为团队、部门、客户交付组或社区。类型只是业务标签，不决定权限，也不隐含上下级。一个成员可同时加入多个协作单元，一个单元可访问多个资源，同一资源可授权多个单元。现有部门树用于人事和数据范围，不能自动等同项目访问权。

资源接口遵守 `can(subject, action, resource)`：subject 必须是租户内有效成员；action 为 READ / WRITE / MANAGE；resource 当前实现 Project，Task 与 File 继承其项目访问边界。未来可增加知识库等资源适配器，不让核心授权依赖具体产品页面。

## 授权规则

- 组织级 RBAC 决定允许执行的功能，资源授权决定允许操作的对象，两者取交集。
- 项目可见性为 ORGANIZATION 或 RESTRICTED。既有项目默认组织可见，保证兼容。
- 组织 OWNER/ADMIN 和项目负责人可管理项目；受限项目其他成员必须通过未归档协作单元取得授权。
- READ / WRITE / MANAGE 按级别包含；资源管理授权不会授予组织管理员身份。
- 单元负责人只管理本单元成员；分配资源授权还需拥有目标资源 MANAGE 权限。
- 活跃单元不能移除/降级最后一名有效负责人；单元归档后授权失效。
- 成员停用、移除、授权撤销在后续 HTTP 请求生效；项目 WebSocket 连接周期复校，最长 30 秒撤销窗口。
- 文件共享链接是显式的额外授权能力；既有共享在项目变为受限后仍有效，须按共享到期规则治理。

## Stripe 作为订阅权威

借鉴 portfolio-site 的官方 SDK、托管收银台和原始体验签，不复用其一次性赞赏状态机。

服务端 `STRIPE_PRICE_MAP` 将本地套餐/周期映射到 Stripe Price，前端不能传金额、Price 或客户编号。组织绑定唯一 Stripe Customer。Checkout 返回不授予权益；签名事件触发对账，锁住组织后读取 Stripe 当前订阅，避免乱序事件覆盖较新状态。事件去重、订阅快照、权益与审计在同一事务内提交。

ACTIVE/TRIALING 授予映射套餐；PAST_DUE、UNPAID、PAUSED、CANCELED 默认收回付费权益至 FREE（欠费不继续宽限，后续可配置业务政策）。本地生命周期任务仅处理 sandbox 订阅。已有 Stripe 订阅通过 Customer Portal 管理，避免重复订阅。对账失败返回非成功状态供 Stripe 重试，也提供组织管理员对账端点恢复。

## 复用边界

后续 SaaS 复用租户上下文、身份、RBAC、资源策略、计费、审计和运行工具。产品模块实现资源适配器及自己的状态机。当前是可复用源码底座，尚不宣称已完成跨应用身份提供商或独立发布 SDK。
